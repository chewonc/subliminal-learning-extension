## 1. Research question

Does one transmission effect appear on Qwen2.5-7B-Instruct with the unmodified
repo: does a student fine-tuned on numbers generated by a cat-loving teacher
name "cat" more often than a control student fine-tuned on numbers generated
by the same teacher with no system prompt?

## 2. Hypothesis (working)

The cat student's P(cat) under the numbers-prefix animal evaluation exceeds
the control student's by at least 0.2, with non-overlapping 95% CIs across the
50 questions.

### 4.3 Control

The control student (trained on regular numbers) is the paper's own control;
it separates "trained on numbers" from "trained on cat numbers".

### 4.4 Metric and uncertainty

`compute_p_target_preference("cat", rows)` from `sl/evaluation/services.py`
(per-question fraction of completions containing "cat", lowercased; 95% CI
over the 50 per-question means via `stats_utils.compute_ci`), or equivalently
count rows whose completion contains "cat" per question and average.

One seed each. "One seed is enough for a smoke test, not for a claim."

## Revision guide (not part of the paper)

**Success criterion (verbatim).** "Pass if the cat student exceeds the control
by at least 0.2 with non-overlapping 95% CIs across the 50 questions."

**Stop / pivot criterion (verbatim).** "Below 0.15 means a setup problem
(prompt mismatch, wrong token, wrong eval), not a null."

**Why this is the minimum (verbatim intent).** Dropping the control leaves you
unable to separate "trained on numbers" from "trained on cat numbers".
Dropping the prefix eval loses most of the Qwen signal. One seed is enough for
a smoke test, not for a claim.

**Negative-result meaning.** Per the stop criterion, a low result is read as a
setup problem to diagnose, not as evidence against subliminal learning.

**Known blockers and their pre-stated fallbacks (from the plan).**
- Compute nodes without internet: pre-download the model (step 2); the HF
  push in steps 5–6 still needs outbound access; the only fix is a one-line
  local-save change, made only with user approval.
- `vllm==0.10.0` or Unsloth failing against the cluster CUDA driver: try a
  newer vLLM pin in a scratch env; if that fails, use the cloud fallback
  (RunPod, about $1–5.25).
- Optional 10-sample debug run (`build_dataset_cfg("cat","animal",debug=True)`)
  needs a one-line config addition; only with user approval.
